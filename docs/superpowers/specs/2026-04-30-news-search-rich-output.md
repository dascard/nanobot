# News Search 富文本输出设计

## 背景

当前 `news_search` 输出最初是偏日志风格的纯文本，后来收成了富 Markdown，再进一步改成工具直接生成整页 HTML。

最后这一步虽然观感更好，但结构完全依赖工具层拼装，顶部摘要区也没有真正利用模型的“总结能力”；如果继续让模型直接写整页 HTML，又会把版式稳定性丢给模型，容易跑格式。

QQbot 当前已经具备：

- 对复杂 Markdown 自动调用 `md_to_pic`
- 对常见 HTML 标签做复杂内容识别

但渲染入口仍是 Markdown 优先，导致 HTML 模板的表达力没有被真正用起来。

## 目标

1. `news_search` 顶部摘要区由模型输出**少量结构化字段**，而不是自由生成整页 HTML。
2. HTML 最终版式完全由代码模板控制，QQbot 继续识别并渲染图片。
3. 保留原有信息密度：检索决策、来源、正文摘要、价值提醒。
4. 让最终视觉更接近“资讯海报”，同时保证格式稳定。

## 方案

### 1. 模型只输出最小结构化摘要

模型输出严格 JSON，只包含：

- `title`
- `subtitle`
- `summary`
- `highlights`
- `alerts`
- `closing`

字段数量刻意压低，避免大量标签或自由 HTML 导致格式不稳。

### 2. 代码负责固定 HTML 模板

报告结构由代码拼装：

- 顶部标题区
- 概览元信息区
- 今日结论
- 重点速览卡片
- 机会关注卡片
- 来源索引表格
- 延伸阅读条目
- 一句收尾

使用内联 CSS + 语义化 HTML，避免依赖外部资源。

模型输出解析失败时，直接退回 deterministic fallback，保证页面始终可生成。

### 3. 保留持久化

`chat_logs` 仍写入最终报告文本，不改变当前审计和检索路径。

### 4. 提示词补充

在主提示词中补一句：

- 当 `news_search` 返回 HTML 资讯卡片时，优先原样转发，不要压平成口语或改写成 Markdown。

这样能提高模型把工具结果原样转发给 QQbot 的概率，但最终格式正确性不依赖模型自觉。

### 5. QQbot 侧渲染分流

增加一个简单分流：

- 如果内容看起来是完整 HTML 卡片，并且存在 `html_to_pic`，优先用它
- 否则继续沿用 `md_to_pic`

这样不会破坏现有 Markdown 渲染链路。

## 验证

1. 单测验证结构化 JSON 解析成功时，固定模板会正确插值。
2. 单测验证 `news_search` 输出仍为 HTML，包含结论、速览、来源索引。
3. 单测验证标题、URL、摘要内容仍在输出中。
4. 校验 QQbot 会把 HTML 片段识别成可渲染内容。
5. 运行相关测试，确认桥接保真路径未回归。
