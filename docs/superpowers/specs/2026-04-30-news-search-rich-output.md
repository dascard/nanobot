# News Search 富文本输出设计

## 背景

当前 `news_search` 输出是偏日志风格的纯文本，包含：

- `News intelligence report`
- `DeepSearchDecision`
- 多个 `Result N`
- 长段正文摘录

这类输出虽然信息完整，但不适合 QQbot 侧现有的图片渲染链路。QQbot 当前已经具备：

- 对复杂 Markdown 自动调用 `md_to_pic`
- 将渲染结果以图片形式发送

因此不需要新增一条专门的 HTML 回传接口，优先让 `news_search` 直接产出稳定、可渲染的富 Markdown。

## 目标

1. `news_search` 输出对用户可直接阅读，而不是偏调试日志。
2. 输出天然触发 QQbot 的复杂 Markdown 检测，从而自动渲染为图片。
3. 保留原有信息密度：检索决策、来源、正文摘要、价值提醒。
4. 尽量不改动主聊天链路，不新增服务端渲染接口。

## 方案

### 1. 工具输出改为富 Markdown

报告结构：

- 一级标题：查询主题
- 引导摘要：查询词、是否启用深搜、命中结果数
- 重点提醒：高价值模型/价格/免费信号
- 结果概览表格：序号、标题、来源、质量分
- 详细条目：标题、链接、摘要、检索策略

这样天然包含：

- 标题 `#`
- 表格 `|...|`
- 列表

可直接命中 QQbot 当前的 `is_complex_markdown()` 逻辑。

### 2. 保留持久化

`chat_logs` 仍写入最终报告文本，不改变当前审计和检索路径。

### 3. 提示词补充

在主提示词中补一句：

- 当 `news_search` 返回结构化资讯报告时，优先保留其 markdown 结构输出，不要压平成碎片化口语。

这样能提高模型把工具结果原样转发给 QQbot 的概率。

### 4. QQbot 侧兼容增强

如果需要，可补强复杂渲染检测：

- 识别 Markdown 表格
- 识别原生 HTML 片段（可选）

本次以 Markdown 为主，不依赖纯 HTML。

## 验证

1. 单测验证 `news_search` 输出包含标题/表格/详细条目。
2. 单测验证旧的标题、URL、摘要内容仍在输出中。
3. 检查 QQbot `is_complex_markdown()` 对该输出返回 `True`。
4. 运行工具级测试，确认回归通过。
