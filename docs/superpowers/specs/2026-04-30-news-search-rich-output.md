# News Search 富文本输出设计

## 背景

当前 `news_search` 输出最初是偏日志风格的纯文本，后来收成了富 Markdown，但仍然偏“检索工作台”，不够像可直接发给用户的资讯卡片。

QQbot 当前已经具备：

- 对复杂 Markdown 自动调用 `md_to_pic`
- 对常见 HTML 标签做复杂内容识别

但渲染入口仍是 Markdown 优先，导致 HTML 模板的表达力没有被真正用起来。

## 目标

1. `news_search` 输出改为原生 HTML 卡片，而不是继续依赖简单 Markdown。
2. QQbot 识别 HTML 卡片后优先走 HTML 渲染，再回退 Markdown。
3. 保留原有信息密度：检索决策、来源、正文摘要、价值提醒。
4. 让最终视觉更接近“资讯海报”，而不是工具报告。

## 方案

### 1. 工具输出改为原生 HTML 模板

报告结构：

- 顶部标题区
- 概览元信息区
- 今日结论
- 重点速览卡片
- 机会关注卡片
- 来源索引表格
- 延伸阅读条目

使用内联 CSS + 语义化 HTML，避免依赖外部资源。

### 2. 保留持久化

`chat_logs` 仍写入最终报告文本，不改变当前审计和检索路径。

### 3. 提示词补充

在主提示词中补一句：

- 当 `news_search` 返回 HTML 资讯卡片时，优先原样转发，不要压平成口语或改写成 Markdown。

这样能提高模型把工具结果原样转发给 QQbot 的概率。

### 4. QQbot 侧渲染分流

增加一个简单分流：

- 如果内容看起来是完整 HTML 卡片，并且存在 `html_to_pic`，优先用它
- 否则继续沿用 `md_to_pic`

这样不会破坏现有 Markdown 渲染链路。

## 验证

1. 单测验证 `news_search` 输出为 HTML，包含结论、速览、来源索引。
2. 单测验证标题、URL、摘要内容仍在输出中。
3. 校验 QQbot 会把 HTML 片段识别成可渲染内容。
4. 运行相关测试，确认 Markdown 路径未回归。
