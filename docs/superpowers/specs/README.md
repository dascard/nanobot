# 设计文档

每次非平凡功能（≥3 个文件或新能力）先在 `brainstorming` 技能流程中产出设计文档，
以 `YYYY-MM-DD-<topic>.md` 格式存放在此目录。

## 规范

- 文件命名：`2026-04-27-history-refactor.md`
- 必须章节：Context（为什么）、Design（怎么做）、Files to Modify、Verification
- 提交前通过 `spec self-check`（占位符扫描、一致性检查、范围检查、模糊性检查）

## 审批流程

1. 头脑风暴 → 产出 spec 草稿
2. 规格自检 → 修复问题
3. 用户审查 → 批准
4. writing-plans → 产出实现计划
