# 超级用户单一配置与历史脱敏设计

## 背景

项目曾同时接受三个环境变量名称，并允许数据库设置覆盖超级用户列表。私聊
guardrail 又直接读取旧的单值变量，导致权限集合、主动外呼目标和管理页面看到
的配置可能不一致。真实用户标识还出现在示例、测试、生成快照、提交消息和
Git 作者邮箱中，普通增量提交无法消除历史暴露。

本设计将超级用户配置收敛为一个环境变量，并通过一次敏感数据历史重写删除
所有 Git 可达记录中的真实标识。

## 目标

- 唯一运行时入口为 `NANOBOT_SUPER_USER_IDS`。
- 所有权限判断和主动外呼目标使用同一个标准化集合。
- 数据库和 Admin WebUI 不再保存或编辑超级用户 ID。
- Admin API、审计详情和页面不返回完整超级用户列表。
- 当前源码、文档、测试和生成物不包含真实用户标识。
- Git blob、提交消息、作者和提交者邮箱不包含真实用户标识。
- 远端历史重写后可验证，且不会混入本地 stash 或内部 checkpoint。

## 非目标

- 不修改 QQbot 端或现有 QQ push 协议。
- 不删除业务数据库中的聊天、用户或主动外呼业务记录。
- 不承诺通过 force push 自动清除第三方 fork、旧 clone 或 GitHub 缓存对象。

## 配置契约

`config.py` 只读取：

```text
NANOBOT_SUPER_USER_IDS
```

变量为空或未设置时得到空集合；支持英文逗号和中文逗号分隔。旧环境变量
名称、旧 Python 配置常量和数据库键 `bot.super_user_ids` 全部从运行时代码、
配置注册表和管理页面删除，不再提供兼容回退。

`core.identity.get_super_user_ids()` 返回启动时解析集合的防御性副本，
`is_super_user_id()`、主动外呼调度和 Admin 手动执行都只调用该接口。Prompt
身份上下文只接收 `is_super_user` 布尔值，不再注入完整列表。私聊 guardrail
不再直接读取配置模块。

启动时会把已有运行时模板中的旧 `super_user_id` 占位符迁移为
`is_super_user`，避免持久化模板在升级后编译失败；迁移结果只包含当前发送者
是否为超级用户，不包含任何超级用户 ID。

修改环境变量后必须重启服务。`.env.example` 仅提供空值示例，不包含任何真实
或可投递目标。

## Admin 与敏感信息边界

主动外呼设置接口不再管理 `bot.super_user_ids`。状态接口只返回：

```json
{
  "super_user_configured": true,
  "super_user_count": 1
}
```

它不返回完整 ID。业务日志接口将目标 ID 和包含目标 ID 的幂等键替换为稳定短
指纹；手动执行和模拟响应也只返回目标短指纹。服务内部仍使用真实目标执行，
但日志和审计不得输出原值。业务日志筛选只接受目标指纹，避免原始 ID 进入
HTTP 查询字符串和访问日志。

数据库迁移删除 `system_settings` 中的旧配置行，并将以该键为目标的既有 Admin
审计详情替换为固定脱敏对象。迁移是幂等的，不删除聊天、用户或主动外呼业务
记录。

## 当前工作区迁移

根目录 `.env` 中旧键名原位改为 `NANOBOT_SUPER_USER_IDS`，值不打印到终端、
补丁或提交。运行数据库先创建 SQLite 在线快照，再删除旧系统设置并脱敏对应
审计记录。

未跟踪的 Playwright 页面快照包含真实会话数据，整体删除并将目录加入忽略
规则。已跟踪的 `.pyc` 和 `__pycache__` 从当前树及完整历史删除。

## Git 历史重写

历史重写同时执行四类过滤：

1. 将真实用户标识替换为不可投递的统一虚构数字标识。
2. 对提交和 tag 消息执行相同替换。
3. 将包含真实标识的旧作者、提交者和 tagger 邮箱改为 GitHub noreply 邮箱。
4. 从所有历史删除 `.pyc`、`__pycache__`、Playwright 快照和误提交数据库。

重写前先把仓库级 `user.email` 改为 noreply 地址。使用 `git-filter-repo` 的
敏感数据模式重写本地所有 refs；内部 checkpoint 直接删除，不推送本地分支或
stash。远端仅更新 `master`，并以重写前远端 SHA 作为 `--force-with-lease`
租约，防止覆盖清理期间出现的新远端提交。

## 验证

- 配置模块不存在旧环境变量名称，唯一变量正确解析列表和空值。
- guardrail、身份变量和主动外呼读取同一个集合。
- Admin 设置接口拒绝旧数据库键，状态和日志响应不返回原始目标。
- 数据迁移删除旧设置并脱敏既有审计，重复执行结果相同。
- 完整 `pytest`、WebUI 构建和 Git diff 检查通过。
- 当前树、所有 refs、提交消息和 author/committer/tagger 邮箱均无真实标识。
- 远端 fresh mirror clone 执行同样扫描无命中。

## 发布影响

这是配置破坏性变更。部署必须在受 Git 忽略的 `.env` 或等价运行环境中设置
`NANOBOT_SUPER_USER_IDS`，并重启全部读取该环境文件的服务。旧 Admin 页面和
数据库设置不再生效。

历史重写会改变全部受影响提交 SHA。协作者必须停止推送并重新 clone；不能把
旧 clone 普通 merge 回新历史。force push 无法清除 fork、PR refs 和 GitHub
缓存，完成后仍需按 GitHub 敏感数据清理流程处理服务端残余引用。
