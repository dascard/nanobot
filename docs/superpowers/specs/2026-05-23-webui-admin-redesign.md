# WebUI 管理台重设计

## 背景

Nanobot WebUI 已经承载模型路由、Prompt Runtime V2、AgentRun、LLM 日志、Reply 评估、贴纸治理等运维功能，但现有界面主要问题是：

- 桌面端信息层级弱，导航平铺过长，重点页面控件密度失控。
- 移动端固定侧栏占据视口，主内容被压缩到不可用。
- 表单控件依赖占位符或视觉上下文，缺少稳定 label / aria-label。
- Prompt 编排 canvas 是鼠标优先的自绘交互，缺少小屏和键盘可访问降级。
- 深色视觉语言过于单一，低对比次级文本过多。
- 局部仍使用 emoji 作为操作图标，不符合后台工具的一致性。

## 设计目标

- 管理台第一屏直接进入可操作后台，不做营销式 landing。
- 采用数据密集型后台布局：紧凑、可扫描、可过滤、可钻取。
- 移动端至少能完成导航、查看列表、筛选、提交表单，不出现固定侧栏挤压主内容。
- 复杂页面按工作流分区，常用操作在页面顶部或当前区块头部，危险操作清晰隔离。
- 所有可交互控件具备可见文本、`aria-label` 或关联 label。
- Prompt flow 在桌面保留 canvas，在小屏提供结构化列表降级。
- 统一基础组件的圆角、边框、间距、状态色和焦点态。

## 视觉系统

- 设计系统：`design-system/nanobot-admin/MASTER.md`
- 形态：Data-Dense + Drill-Down。
- 基础背景：深色运维台，保留代码和日志阅读舒适度。
- 主色：靛蓝用于导航和选中态，翡翠绿用于成功和主要提交。
- 状态色：红色表示失败/危险，琥珀表示警告，蓝色表示信息，紫色只用于少量 Prompt/Trace 分类。
- 圆角：普通卡片和按钮不超过 8px。
- 动效：只保留 150-200ms 的 hover/focus 反馈；尊重 `prefers-reduced-motion`。

## 信息架构

导航按任务域分组：

- 总览：仪表盘。
- 运行链路：Agent Runs、LLM API 日志、Reply 测试、定时任务。
- Prompt：V2 运行预览、V2 模板、V1 模板 / 对比。
- 模型：模型管理、供应商配置。
- 数据：用户、群聊、贴纸、抽样、对话。
- 系统：Prompt Trace、系统配置。

移动端导航使用顶部栏 + 抽屉，不保留常驻侧栏。

## 重点页面

### Prompt Runtime V2

- 运行预览页面必须强调真实 compile 输入与输出，减少原始 JSON 对主要任务的干扰。
- 模板页面桌面保留 canvas，移动端显示节点列表、边列表、当前选中节点编辑入口。
- canvas 操作按钮使用图标或图标 + 文本，提供 title / aria-label。

### Reply 测试与评估

- 区分真实发送、dry-run、评估集维护。
- 新建/编辑 case 的每个输入都必须有 label。
- 结果区域优先展示指标表、失败原因、trace 链接，再展示 JSON。

### LLM API 日志

- 筛选栏使用显式标签，不依赖 placeholder。
- 表格和详情保持可扫描密度，长文本截断但可进入详情。

### 模型管理

- 筛选控件具备 label。
- 候选模型以状态、优先级、成本/能力为主要扫描字段。

### 贴纸治理

- 去掉 emoji 操作按钮，统一使用图标按钮或文本按钮。
- 操作按钮必须有 title / aria-label。

## 非目标

- 不重写后端 API。
- 不引入大型 UI 框架。
- 不一次性拆空 `App.jsx`，但允许引入共享组件和局部结构整理。
- 不把自绘 Prompt flow 一次性替换成 React Flow；本阶段先提供可访问降级和控件治理。

## 验收标准

- 375px 移动视口下主内容宽度不被常驻侧栏挤压，页面无明显水平溢出。
- `App.jsx` 不再包含贴纸治理用 emoji 操作按钮。
- 登录、模型筛选、日志筛选、Reply case 编辑等关键表单控件具有 label 或 aria-label。
- Prompt flow 在小屏存在非 canvas 的结构化降级视图。
- 前端构建通过。
- 通过 Playwright 截图检查桌面和移动端重点页面。
